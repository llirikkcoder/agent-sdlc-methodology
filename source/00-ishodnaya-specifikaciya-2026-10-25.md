# Спецификация системы: AI Agent Framework (Softoscope + Event Sourcing + SDLC Pipeline)

Настоящая спецификация описывает архитектуру и методологию построения **универсального автономного агента**. Система объединяет декларативную модель домена (**Softoscope**), неизменяемый аудит и память (**Event Sourcing**) и строгий конвейер разработки и исполнения задач (**SDLC Pipeline**).

---

## 1. Архитектурный обзор (High-Level Architecture)

Система разделена на три ключевых слоя взаимодействия:

```
+-----------------------------------------------------------------------+
|                             HUMAN OPERATOR                            |
+-----------------------------------------------------------------------+
                                   | (Задачи, подтверждения, границы)
                                   v
+-----------------------------------------------------------------------+
|                    1. SOFTOSCOPE (Доменная карта)                    |
|  - Слой 1: Назначение и Ядро (Цели, Ограничения)                       |
|  - Слой 2: Домен (Сущности, Состояния, Связи)                         |
|  - Слой 3: Процессы (Шаги, Обратимость, HITL-флаги)                   |
|  - Слой 4: Возможности (Привязка Шаг -> MCP Инструмент)               |
|  - Слой 5: Реализация (Код, Маршруты, Миграции, Drift)                |
+-----------------------------------------------------------------------+
           | (Контекст, Границы)                ^ (Проверка drift)
           v                                    |
+-----------------------------------------------------------------------+
|                    2. SDLC PIPELINE (Оркестратор)                    |
|  - Spec-First Execution (Спецификация -> План -> Исполнение)          |
|  - Quality Gates (Линтеры, Тесты, Сторожа)                            |
|  - Human-in-the-Loop (Эскалация необратимых шагов)                    |
+-----------------------------------------------------------------------+
           | (Вызов инструментов)               | (Генерация событий)
           v                                    v
+-----------------------------------------------------------------------+
|                  3. EVENT SOURCING STORE (Память)                     |
|  - Audit Log (Неизменяемая история команд и решений)                   |
|  - Projections (Проекции текущего состояния процессов)                |
|  - Time-Travel & Recovery (Восстановление при сбоях)                  |
+-----------------------------------------------------------------------+

```

## 2. Модуль 1: Softoscope (Спецификация модели домена)

Softoscope поставляет модель предметной области в виде структурированных данных (JSON/YAML Schemas), а не сырого текста в системном промпте.

### 2.1. Спецификация 5 слоев Softoscope

#### Слой 1: Purpose & Core Constraints (Назначение и Границы)

* **Назначение:** Определяет глобальную цель системы и бизнес-инварианты, которые агент **не имеет права нарушать ни при каких обстоятельствах**.
* **Формат данных (`purpose.json`):**

```json
{
  "system_id": "ai_office",
  "purpose": "Автоматизация операционных процессов продаж и контента",
  "hard_constraints": [
    {
      "id": "C001",
      "rule": "Запрещено отправлять коммерческие предложения без согласования суммы > $1000",
      "severity": "CRITICAL"
    },
    {
      "id": "C002",
      "rule": "Запрещено удалять контактные данные клиентов из базы",
      "severity": "CRITICAL"
    }
  ]
}

```

#### Слой 2: Domain (Сущности и Состояния)

* **Назначение:** Декларативное описание графа сущностей, их допустимых состояний и переходов.
* **Формат данных (`domain.json`):**

```json
{
  "entities": {
    "Deal": {
      "attributes": ["id", "amount", "client_id", "stage"],
      "states": ["lead", "qualification", "proposal", "closed_won", "closed_lost"],
      "transitions": [
        {"from": "lead", "to": "qualification"},
        {"from": "qualification", "to": "proposal"},
        {"from": "proposal", "to": "closed_won"}
      ]
    }
  }
}

```

#### Слой 3: Processes (Цепочки процессов)

* **Назначение:** Описание последовательности шагов, исполнителя (человек/агент) и типа действия.
* **Формат данных (`processes.json`):**

```json
{
  "process_id": "deal_onboarding",
  "steps": [
    {
      "step_id": "step_1",
      "name": "Проверка квалификации лида",
      "actor": "agent",
      "is_reversible": true,
      "capability_id": "mcp_crm_get_lead"
    },
    {
      "step_id": "step_2",
      "name": "Отправка счета на оплату",
      "actor": "human_approval_required",
      "is_reversible": false,
      "capability_id": "mcp_billing_send_invoice"
    }
  ]
}

```

#### Слой 4: Capabilities (Связь шагов с инструментами)

* **Назначение:** Каталог MCP-инструментов с классификацией по степени опасности (читающие, правящие, необратимые).
* **Формат данных (`capabilities.json`):**

```json
{
  "capabilities": {
    "mcp_billing_send_invoice": {
      "mcp_server": "finance_mcp",
      "tool_name": "send_invoice",
      "type": "mutating_irreversible",
      "requires_human_gate": true
    }
  }
}

```

#### Слой 5: Implementation (Код и Сторожа Drift)

* **Назначение:** Статическая привязка к коду (маршруты, API, таблицы DB). Инструмент `drift.sh` проверяет, совпадает ли объявленный в слое 3 процесс с реальным наличием кода и MCP-ручек в слое 5.

## 3. Модуль 2: Event Sourcing (Память и Аудит)

Каждое действие агента, изменение состояния или решение сохраняются в идемпотентный лог событий (Event Store).

### 3.1. Схема базового события (Event Schema)

Все события соответствуют общему контракту:

```typescript
interface AgentEvent {
  eventId: string;           // UUID v4
  aggregateId: string;       // ID процесса или сущности (напр. "deal_123")
  timestamp: string;         // ISO 8601
  eventType: string;         // "ProcessStarted", "StepExecuted", "HumanApproved", "StepFailed"
  actor: "agent" | "human" | "system";
  layer: 1 | 2 | 3 | 4 | 5;  // Слой Softoscope, к которому относится событие
  payload: Record<string, any>;
  metadata: {
    correlationId: string;   // Trace ID рабочей сессии
    causationId: string;     // ID события/команды, вызвавшей текущее событие
    modelName?: string;
  };
}

```

### 3.2. Набор основных событий агента

* **`ProcessInitiated`**: Запущен новый экземпляр процесса из Слоя 3.
* **`StepExecutionRequested`**: Агент намеревается выполнить шаг.
* **`HumanApprovalRequested`**: Запрошено подтверждение человека для необратимого (`is_reversible: false`) действия.
* **`StepCompleted`**: Шаг успешно исполнен через MCP capability.
* **`ConstraintViolated`**: Попытка совершить действие, нарушающее правило из Слоя 1.

## 4. Модуль 3: SDLC Pipeline (Исполнение и Контроль качества)

Конвейер SDLC управляет жизненным циклом выполнения задачи агентом от получения промпта до внесения изменений.

### 4.1. Этапы выполнения (Pipeline Stages)

1. **Spec & Scope Phase (Анализ границ):**
* Агент запрашивает через Softoscope MCP данные Слоев 1–3.
* Строит граф исполнения: какими инструментами (Слой 4) будет выполняться каждый шаг процесса.


2. **Static Guard Check (Проверка целостности):**
* Автоматическая валидация: есть ли у каждого шага соответствующий инструмент в коде (Слой 5).
* Если инструмента нет — система мгновенно генерирует ошибку `MissingCapabilityError` вместо того, чтобы агент галлюцинировал.


3. **Step-by-Step Execution & Event Logging:**
* На каждом шаге агент создает событие `StepExecutionRequested`.
* Если шаг отмечен как `is_reversible: false` или `type: mutating_irreversible`, процесс блокируется до получения события `HumanApproved`.


4. **Projection & Verification:**
* После выполнения шага обновляется проекция состояния процесса.
* Проводится проверка соответствия границам Слоя 1.

## 5. Спецификация MCP-Интерфейсов Softoscope (`scope_*`)

Для взаимодействия агента с моделью Softoscope разворачивается отдельный MCP-сервер со следующими инструментами:

```markdown
### 1. `scope_get_purpose`
- **Описание:** Возвращает глобальные цели и бизнес-границы (Слой 1).
- **Параметры:** `{ "system_id": string }`

### 2. `scope_get_process_map`
- **Описание:** Возвращает пошаговую карту процесса, квалификацию шагов (обратимый/необратимый) и привязанные MCP-инструменты (Слои 3–4).
- **Параметры:** `{ "process_id": string }`

### 3. `scope_check_drift`
- **Описание:** Проверяет расхождение между описанным процессом (Слой 3) и реальными ручками в коде (Слой 5). Возвращает список "дыр" в процессах.
- **Параметры:** `{}`

### 4. `scope_get_entity_schema`
- **Описание:** Возвращает описание сущности, ее состояний и разрешенных переходов (Слой 2).
- **Параметры:** `{ "entity_name": string }`

```
