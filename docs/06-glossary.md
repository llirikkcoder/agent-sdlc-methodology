# Глоссарий

Термины ядра. Доменные термины — в README соответствующего примера.

- **Softoscope** — пятислойная декларативная модель системы (назначение, домен, процессы, возможности, реализация), поставляемая агенту как данные.
- **Слой** — один из пяти файлов модели; у каждого своя JSON Schema в `schemas/`.
- **Назначение (purpose)** — слой 1: зачем система, роли, цели, non-goals, жёсткие ограничения.
- **Роль** — участник: человек, агент или системный процесс. Роль с `may_approve` разрешает гейты.
- **Жёсткое ограничение (hard constraint)** — проверяемый инвариант слоя 1 с способом применения: `pre_check`, `gate`, `post_check`, `audit_only`.
- **Сущность** — объект предметной области слоя 2 с идентификатором, атрибутами и, возможно, конечным автоматом состояний.
- **Переход (transition)** — разрешённая смена состояния сущности; у перехода есть исполнитель и признак обратимости.
- **Производное состояние (derived_state)** — состояние, вычисляемое из других сущностей, а не хранимое первично.
- **Процесс** — цепочка шагов слоя 3 вокруг одной сущности-агрегата.
- **Шаг** — единица процесса: исполнитель, роль, возможность, переход, гейт, ветвление, поведение при ошибке.
- **Агрегат (aggregate)** — сущность, чей жизненный цикл ведёт процесс; её идентификатор — идентификатор экземпляра процесса и ключ потока событий.
- **Возможность (capability)** — контракт того, что система умеет: вид (`kind`), эффект (`effect`), роли, входы/выходы, идемпотентность. Не знает, где лежит в коде.
- **Эффект (effect)** — класс влияния возможности на мир: `read`, `write_reversible`, `write_compensable`, `write_irreversible`.
- **Компенсация** — действие, нейтрализующее последствия `write_compensable`-возможности, когда отката нет.
- **Привязка (binding)** — запись слоя 5: где возможность реализована (путь, символ, маршрут, узел графа, инструмент MCP, команда), в каком статусе и чем подтверждено.
- **Статус привязки** — `implemented`, `stub`, `planned`, `deprecated`, `unconfirmed`.
- **Evidence** — чем подтверждена привязка: `code`, `docs`, `manual`, список инструментов сервера.
- **Человеческий гейт (human gate)** — требование решения человека до исполнения шага; порождает `HumanGateRequested` и ждёт `HumanGateResolved`.
- **Правило гейта** — шаг агента/системы обязан иметь гейт при необратимом эффекте, политике возможности или ограничении `enforcement: gate`; условный гейт допустим только для двух последних.
- **Human-in-the-loop (HITL)** — участие человека в автоматическом процессе через гейты и шаги с `actor: human`.
- **Drift** — расхождение между заявленным (слои 3–4) и реальным (слой 5, код). Находки — дыры.
- **Ступени проверок (`checks[].stage`)** — `on_edit` (хук в сессии агента), `static_guard`, `verify`, `pre_merge`; от дешёвой к дорогой.
- **Обратный дрейф (unmodeled)** — в коде есть маршрут, узел графа или таблица, которых нет в слое 5; только предупреждение (ADR-020).
- **Реестр кода** — объявления, извлечённые разбором синтаксиса (`tools/code_inventory.py`): символы, маршруты, узлы графа, таблицы, переменные окружения, плюс снимок исходника.
- **Дыра (MissingCapability)** — шаг без работающей возможности: `not_declared`, `not_bound`, `not_implemented`, `stale`.
- **MissingCapabilityError** — остановка исполнения на Static Guard из-за дыры; фиксируется событием `CapabilityMissing`.
- **Событие** — неизменяемая запись факта по контракту `schemas/event.schema.json`: кто, что, с чем связано (`scope`), в какой цепочке (`correlation_id`).
- **Базовый каталог событий** — четырнадцать типов, которые знает ядро (`ProcessInitiated` … `DriftDetected`).
- **Порог (threshold)** — машиночитаемое условие ограничения `enforcement: gate` по атрибуту сущности; единственный способ сделать гейт на необратимом действии условным.
- **AutoApprovedByRule** — событие автоматического прохождения условного гейта ниже порога, с `constraint_id` и фактическим значением.
- **Системное действие (system_level)** — возможность, меняющая саму систему (миграции, конфигурация, права); всегда под гейтом. Правка кода при зелёных гейтах — не системное действие (ADR-019).
- **Импорт сущности (imports)** — ссылка на сущность другой системы без права менять её состояние.
- **Доменное событие** — тип, объявленный в `domain_events` слоя 2 и привязанный к сущности.
- **Корреляция (correlation_id)** — идентификатор цепочки от запроса до результата; один на все её события.
- **Причинность (causation_id)** — ссылка на событие/команду, вызвавшую данное событие.
- **Идемпотентность** — свойство возможности или команды: повтор не меняет мир второй раз (`natural`, `key`, `none`).
- **Проекция** — состояние, вычисленное из событий: `ProcessInstance`, `PendingGates`, `EntityState`, `AuditTrail`.
- **Static Guard** — детерминированная проверка перед исполнением: валидность модели, отсутствие дыр, известные `pre_check`-правила.
- **Цикл исполнения / цикл поставки** — два контура конвейера: исполнение процесса агентом и изменение модели и кода командой.
- **Сторож качества (check)** — команда из `checks[]` слоя 5 (линтер, тесты, smoke), которую гоняет конвейер.
- **`scope_*`** — инструменты MCP-сервера, отдающего агенту срезы модели только на чтение.
- **Чистота ядра** — отсутствие доменных слов в `schemas/`, `tools/` и модульных документах; проверяется `tools/check_core_purity.py`.
- **Не подтверждено (unconfirmed)** — пометка данных, записанных со слов или из документов и не сверенных с кодом/владельцем.
