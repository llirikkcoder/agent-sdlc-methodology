# ADR-004. Возможность — не обязательно MCP-инструмент

**Контекст.** Исходник называет слой 4 «каталогом MCP-инструментов». Первый же реальный пример (система без MCP-сервера, с HTTP-маршрутами, узлами графа исполнения и функциями) в такой каталог не ложится.

**Решение.** У возможности есть `kind` из перечисления: `mcp_tool`, `http_route`, `function`, `llm_step`, `cli`, `query`, `ui_action`, `external_call`. В слое 5 `location` имеет поля под каждый вид (`route`, `graph_node`, `mcp`, `command`, `symbol`). MCP — один из видов, без привилегий.

**Следствия.**
- Шаг, исполняемый моделью (генерация, классификация, оценка), — возможность `llm_step` со своим контрактом и `metadata.model` в событиях.
- `scope_*`-сервер остаётся MCP-сервером: это интерфейс к модели, а не требование к системе.
- Drift умеет проверять по коду `http_route`, `function`, `graph_node`, таблицы; `mcp_tool` без пути помечает `unverifiable` — подтверждение приходит списком инструментов сервера.
