# ADR-010. Условный гейт на необратимом действии — только по порогу ограничения

**Статус.** Принято 25.10.2026 (развилка Q1; решение делегировано Кириллом, его предложение совпало с альтернативой из `open-questions.md`).

**Контекст.** ADR-003 п. 4 запрещал `condition` на шаге с необратимой возможностью. Исходник же прямо допускает: «запрещено отправлять КП без согласования суммы > 1000 USD» — ниже порога агент действует сам. Строгое правило удваивало ручные согласования и расходилось с замыслом.

**Решение.**
1. На шаге с `effect: write_irreversible` условный гейт допустим **только** с `reason: constraint` и `constraint_id`, указывающим на ограничение слоя 1 с `enforcement: gate` и заполненным `threshold`.
2. `threshold` — машиночитаемый: `{attribute: "Entity.attribute", operator, value, unit?}`. Атрибут — **детерминированное поле сущности слоя 2** (валидатор проверяет его существование). Оценка модели, «уверенность», текстовый вердикт порогом быть не могут.
3. Ниже порога шаг исполняется автоматически, и в журнал обязательно пишется `AutoApprovedByRule` с `scope.constraint_id`, `scope.step_id`, `payload.attribute`, `payload.value` и порогом. Выше порога — обычный `HumanGateRequested`.
4. Гейт по `human_gate_required`, `system_level` и безусловные гейты не меняются.

**Почему так.** Порог — часть ограничения, а не шага: его видно в слое 1 и его можно аудировать. Автопрохождение оставляет след, неотличимый по полноте от решения человека. Валидатор ловит попытку сделать условие на «уверенности».

**Последствия.** Схема `purpose`: `hard_constraints[].threshold`. Валидатор: три новые проверки (условие на необратимом без порога — ошибка; `threshold.attribute` не в слое 2 — ошибка; порог у ограничения без `enforcement: gate` — предупреждение). Пример `ai-office-sales`: C001 с порогом, шаг `send_offer` условный. Заменяет ADR-003 п. 4.
