# ADR-005. В событии — `scope`, а не `layer: 1..5`

**Контекст.** Исходный контракт события несёт поле `layer: 1 | 2 | 3 | 4 | 5` — «слой, к которому относится событие».

**Решение.** Вместо номера — объект `scope` с явными ссылками: `system_id`, `process_id`, `step_id`, `capability_id`, `entity`, `constraint_id`. Номер слоя при необходимости выводится: есть `constraint_id` → слой 1, `entity` → 2, `step_id` → 3, `capability_id` → 4.

**Почему.** Ссылки проверяемы (валидатор сверяет их с моделью), а число — нет. Одно событие часто касается нескольких слоёв сразу (шаг + возможность + переход сущности); число заставило бы выбирать. Проекции и аудит фильтруют по ссылкам, а не по слою.

**Также.** Ключи событий переведены в `snake_case` (в исходнике — `camelCase`), чтобы совпадать со слоями (ADR-008). `aggregate` разделён на `kind` (`process_instance | entity`), `type` и `id`, потому что поток событий процесса и поток событий сущности — разные агрегаты с разной нумерацией `sequence`.
