# ADR-020. Реестр кода, обратный дрейф, снимок исходника и черновик слоя 5

**Статус.** Принято 26.10.2026 (решение Кирилла по всем четырём пунктам). Уточняет ADR-006: для Python-кода сверка идёт по реестру, а не по тексту.

**Контекст.** ADR-006 сделал сверку с кодом поиском по тексту, чтобы обойтись без парсеров. У этого две слабости:
- строка `def foo` в docstring или в мёртвом тексте засчитывается как объявление;
- drift идёт только от модели к коду и не видит обратного: в коде появился маршрут или таблица, а модель о них молчит.

Кроме того, находку drift нельзя было воспроизвести: в отчёте не было, против какой версии кода он получен.

**Решение.**
1. **Реестр кода** (`tools/code_inventory.py`). Строится стандартным модулем `ast`, без установки проекта. Для Python-файлов, включая скрипты без расширения с python в shebang, в реестр попадают:
   - функции, классы и методы с полным именем;
   - маршруты с учётом prefix роутера;
   - узлы графа (`add_node`);
   - таблицы (`__tablename__`);
   - переменные окружения.

   Привязки к Python-файлам `drift --repo` сверяет по реестру. Файлы других языков, как и раньше, сверяются по тексту, а файл, который не удалось разобрать, — дыра `stale` с причиной.
2. **Обратный дрейф: дыра `unmodeled`.** Маршрут, узел графа или таблица есть в коде, но не описаны в слое 5. Уровень — **всегда WARN, в том числе в `--strict`**: не всё в коде обязано быть в модели, служебный маршрут или таблица миграций — не процесс. Функции и переменные окружения в обратный дрейф не входят: их слишком много, и в модели для них нет места. Проверку можно выключить ключом `--no-reverse`.
3. **Снимок исходника.** С `--repo` отчёт drift содержит `snapshot`:
   - `commit` и `dirty` (если это git);
   - число файлов;
   - общий хэш файлов.

   Его же кладут в `DriftDetected.payload.snapshot`, чтобы находку можно было повторить на той же версии кода.
4. **Черновик слоя 5** (`tools/draft_bindings.py`). По реестру он предлагает кандидатов для возможностей без привязки: обработчик маршрута, узел графа, функцию или метод с тем же именем. Каждая предложенная привязка имеет `status: planned` и `evidence: "draft …"`, а файлы инструмент не пишет. Правило «слой 5 не правится автоматически по коду» сохраняется: черновик — подсказка, решает человек.

**Почему так.** Разбор синтаксиса Python есть в стандартной библиотеке, так что точность не стоит зависимостей (ADR-009). Обратный дрейф полезен как сигнал, но если сделать его блокирующим, модель начнут раздувать служебными привязками ради зелёного CI. Снимок дешёвый и превращает «у меня drift красный» в воспроизводимый факт.

**Последствия.**
- В `tools/` три изменения: `code_inventory.py`, `draft_bindings.py`, а `drift.py` получил `--no-reverse` и поле `snapshot` в `--json`.
- В `docs/01` таблица дыр дополнена строкой `unmodeled`.
- `holes_to_tasks.py` знает действие для `unmodeled`.
- Тесты на синтетическом репозитории: `tests/test_code_inventory.py`.
- Другие языки — следующий шаг: реестр расширяется по тому же контракту (символы, маршруты, таблицы).
