# ADR-017. Неподтверждённые ограничения — градация по severity

**Статус.** Принято 25.10.2026 (развилка Q8; Кирилл: critical блокирует, high предупреждает, medium информирует).

**Контекст.** Ограничение со `status: unconfirmed` (как C007 в примере regulated-document-qa: «досье не покидают контур», модель хостится неизвестно где) раньше только показывалось. Вопрос: запрещать ли исполнение процесса.

**Решение.** Drift-дыра `unconfirmed_constraint` для каждого процесса, к которому применимо неподтверждённое ограничение:

| severity | цикл поставки (`drift.py`) | runtime Static Guard (`drift.py --strict`) |
|---|---|---|
| `critical` | WARN | **ERROR — исполнение блокируется** |
| `high` | INFO | WARN |
| `medium` | INFO | INFO |

Модель с неподтверждённым critical-ограничением можно сливать и проверять, но нельзя исполнять процессы под ним, пока человек не подтвердит или не снимет ограничение.

**Почему так.** Блокировать поставку значило бы запрещать описывать честно; блокировать исполнение — ровно то, что нужно: агент не действует там, где граница не подтверждена.

**Последствия.** `drift.py`: новая дыра. Пример regulated-document-qa: `make check` зелёный (WARN), `make drift-strict` показывает блокировку.
