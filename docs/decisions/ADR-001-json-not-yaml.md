# ADR-001. JSON, а не YAML

**Контекст.** Исходная спецификация допускает «JSON/YAML Schemas». Нужен один формат для пяти слоёв, событий и примеров.

**Решение.** JSON (UTF-8, отступ 2) для всех файлов слоёв и образцов событий. Схемы — JSON Schema draft 2020-12.

**Почему.**
- Валидация и инструменты без зависимостей: `json` есть в стандартной библиотеке Python, YAML — нет (`PyYAML` — внешний пакет). Требование «без тяжёлых зависимостей» выполняется.
- JSON Schema валидирует JSON напрямую; YAML пришлось бы сначала конвертировать, и ошибки указывали бы не на строки исходника.
- Один формат — одна истина: нет спора «якоря и многострочные строки против однозначности».

**Цена.** Комментариев в JSON нет: пояснения — в полях `description`/`notes` и в README примера. Правки длинных файлов руками менее удобны; компенсируется валидатором с путями `$.processes[…].steps[…]`.

**Отменяется, если** команда стандартизирует YAML во всём контуре и готова к зависимости — тогда конвертер YAML→JSON перед валидацией, схемы не меняются.
