# ADR-003. Обратимость и происхождение гейта

**Контекст.** В исходнике обратимость закодирована трижды: `is_reversible` на шаге, `type: mutating_irreversible` на инструменте, `requires_human_gate` на инструменте. Три поля могут противоречить друг другу, и непонятно, какое главное.

**Решение.**
1. Обратимость — свойство **возможности** (`effect`), потому что она определяется тем, что действие делает с миром, а не тем, в каком процессе его вызвали. Четыре класса: `read`, `write_reversible`, `write_compensable` (обязательна `compensation`), `write_irreversible`.
2. Гейт — свойство **шага** (`human_gate`), потому что решать «нужен ли человек здесь» можно только зная контекст процесса и роль утверждающего.
3. Связь задаётся **правилом**, которое проверяет валидатор: шаг агента/системы обязан иметь гейт, если возможность необратима, или помечена `human_gate_required`, или на неё указывает ограничение `enforcement: gate`.
4. Гейт может быть условным (`condition`) по политике или ограничению. Для необратимого действия — только по ограничению с машиночитаемым порогом (уточнено в ADR-010).
5. На переходе слоя 2 есть `reversible` — это про автомат сущности (есть ли обратный переход), не про возможность; валидатор предупреждает, если `reversible: true` без обратного перехода.

**Почему так.** Одно место для каждого факта; противоречие ловится машиной, а не ревьюером. Агент видит на шаге готовый ответ «нужен ли человек», не вычисляя его из трёх полей.

**История.** Первая редакция п. 4 запрещала условие на необратимом действии вовсе; это было строже исходника (КП ниже порога отправлялось без согласования). Развилка Q1 решена в ADR-010.
